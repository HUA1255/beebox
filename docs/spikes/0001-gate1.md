# Gate 1 Spike 报告：Qwen3-ASR + ForcedAligner + pyannote

日期：2026-10-31  
样本：本地会议录音 `0304.m4a`（82.7 分钟，单声道 48kHz AAC）  
环境：Windows + RTX 2080 Ti 22GB（本次实际峰值未超过 8.6GB）、Python 3.12、torch 2.14.1+cu126、transformers 5.22.1  
隔离目录：独立的 spike 目录（未改主线代码）

## 结论

**Gate 1 模型可行性通过（30 分钟连续跑按用户要求跳过）。** Qwen3-ASR-1.7B fp16、Qwen3-ForcedAligner-0.6B、pyannote community-1 在本机可跑通，能输出带说话人和字级时间戳的 TXT/MD/SRT；16GB 显存上限可行。

需要带进 Gate 2 的问题：

- pyannote 对短插话/主持人会过分割，同一人可能被拆成多个标签。
- 说话人切换点会把一句话切断，需要跨段合并与边界平滑。
- 长音频分块、跨块文本合并、Docker 内完整管线尚未验证。
- torchcodec 在 Windows 上加载 DLL 失败，已用 soundfile + 内存波形绕开；Docker/Linux 内仍建议避免 torchcodec 路径。

## 说话人分离结果

完整 82.7 分钟：

- 6 个说话人，385 个 turn。
- 主体两位：SPEAKER_02 约 2204s，SPEAKER_04 约 2037s；其余为短插话/噪声。
- 5 分钟多人窗口（37:15–42:15）：SPEAKER_02 133.8s、SPEAKER_04 123.5s，另有短 turn。

多人窗口的实际文本能看到交接：

- `[00:02:22] 说话人4：嗯，然后那接下来的话进入我们最后一个topic……`
- `[00:02:44] 说话人5：位下午好。那我今天讲的topic……`

## 质量问题

1. **过分割**：短插话（“啊，”）和主持人被拆成独立标签；同一主持人可能对应 SPEAKER_02 和 SPEAKER_04。
2. **切句**：说话人切换点会把一句话切成两段，例如“资源。OK，比如说……”被分到两个人。
3. **重叠语音**：短 turn 与主说话人重叠时，字符可能全部归给主说话人（本次 SPEAKER_01 的 0.34s/0.36s turn 没有分到字）。
4. **ASR 识别误差**：专有名词（Ratis、Open Core 等）和口语停顿有错字；不影响“可用”判断，但说明需要热词/上下文。
5. **末尾时间**：5 分钟片段的字符时间戳在 277.44s 之后压缩，后 22s 可能是静音；需要在 Gate 2 用 VAD/分块确认。

## 技术发现

- transformers 5.22.1 **原生支持** Qwen3-ASR 和 Qwen3-ForcedAligner，不需要装 git 版。
- `AutoModelForMultimodalLM` + `AutoProcessor.apply_transcription_request` 可直接吃 numpy 音频（16kHz），不需要文件路径。
- `prepare_forced_aligner_inputs` + `decode_forced_alignment` 输出字符/词级时间戳；时间戳 token 不含标点，需要按原文回填标点。
- pyannote community-1 可从 ModelScope 下载，**不需要 HF token**；`Pipeline.from_pretrained(local_dir)` 可用，传入内存 waveform 可绕开 torchcodec。
- torchcodec 0.17.0 在 Windows 上加载 DLL 失败；Gate 2 的 Docker/Linux 管线仍建议用 soundfile 读音频，避免依赖 torchcodec 的解码路径。
- 模型权重：ASR 4.08GB + Aligner 1.84GB + pyannote 约 33MB。

## 未验证 / 风险

- 30 分钟连续分块跑按用户要求跳过；Gate 2 用完整 82.7 分钟做端到端功能验收。
- 完整 82.7 分钟 ASR 没有跑；只验证了 5 分钟片段和完整分离。
- 分块、跨块文本合并、失败重试、断点续跑尚未实现/验证。
- Docker 内完整模型管线未跑；只验证了 Docker GPU 直通。
- 3 小时录音未验证；按 3 小时设计的目标仍需 Gate 2 用分块管线确认。
- 组合阶段（ASR + Aligner + pyannote 同进程/同容器）的显存未实测。

## Gate 2 建议

1. 冻结 API 契约：Job、Chunk、Segment、Speaker、Export。
2. 后端 Docker：CUDA 镜像、模型 volume、soundfile 音频读取、Qwen3-ASR fp16、ForcedAligner、pyannote。
3. 分块：60–180 秒、VAD/静音切分、0.3–0.5 秒重叠、跨块文本合并。
4. 分离后处理：短 turn 合并、主持人/讲者标签稳定化、重叠标记。
5. 前端：复用 asrbox React UI 的 Web 化版本，补说话人改名、导出。
6. 用完整 `0304.m4a` 做一次端到端功能验收（不做性能基准）。
